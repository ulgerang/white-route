# 에셋 목록 및 제작 기준

> 문서 상태: 제작 계획 초안 · 문서 기준일: 2026-10-03 · 모든 수량은 범위 계획이며 엔진/플랫폼 결정 후 확정한다.

## 1. 목적과 범위

이 문서는 《하얀 대륙: 펭귄 익스프레스》의 아트·애니메이션·UI·오디오 에셋을 제작, 검수, 통합하기 위한 목록이다. 제품 범위는 [제품 비전](../00_product/vision.md)과 [콘텐츠 제작 계획](../03_content/content-plan.md), 상호작용 규칙은 [게임플레이 시스템](../02_game-design/gameplay-systems.md), 시각 기준은 [비주얼·애니메이션·오디오 방향](visual-audio-direction.md)을 따른다.

에셋은 세 단계로 나눈다.

- **회색 박스 프로토타입:** 형상·색 블록과 임시 효과음으로 조작, 시야, 판정을 검증한다. 최종 모델링 전에 위험·수집의 실루엣과 애니메이션 상태를 확인한다.
- **첫 공개 빌드:** 1개 원정/4개 구간, 해안·크레바스 2개 환경, 날씨 1종, 기본 캐릭터 1종을 알아볼 수 있는 완성도로 제작한다. 상호작용 에셋 5종의 위험/수집 배분은 세부 콘텐츠 선정 때 확정한다.
- **초기 정식 출시 목표:** 5개 환경 테마와 20개 수제 구간, 위험물 최대 8종, 주요 캐릭터 4종 범위에 맞춘다. 환경 타일과 공용 프롭을 재사용하되, 각 구간의 패턴과 랜드마크는 구별되게 구성한다.

> 원작 영상 캡처와 3×3 분석 시트는 조사 참고 자료다. 게임 에셋으로 재사용하거나 추출하지 않는다. 원작의 명칭, 캐릭터 외형, 픽셀 아트, 음악을 모사하지 않고 독립적으로 제작한다.

## 2. 우선순위와 상태

| 표기 | 의미 |
|---|---|
| P0 | 코어 주행 검증에 반드시 필요. 임시 에셋도 게임 판정을 정확히 표현해야 한다. |
| P1 | 수직 슬라이스/첫 공개 빌드에 필요. 게임의 시각·음향 품질 기준을 충족한다. |
| P2 | 정식 출시 콘텐츠 또는 변주에 필요. 기본 루프를 검증한 뒤 제작한다. |
| 후보 | 채택 여부를 검증한 뒤 제작한다. 현재 범위에 확정 포함하지 않는다. |
| 계획 | 목록화됐으나 제작/승인은 시작되지 않았다. |
| 검수 | 엔진 내 통합 후 가독성·동작·성능을 확인한다. |
| 승인 | 담당 검수 기준을 통과해 빌드 사용이 가능하다. |

수량의 `1세트`는 재사용 가능한 에셋 묶음을 뜻한다. 환경별 실제 프롭 수, 애니메이션 클립 분할, 음성 필요 여부는 제작 예산과 엔진이 결정된 뒤 에셋 브레이크다운에서 세분화한다.

현재 마스터 목록의 모든 항목은 `계획` 상태다. 담당자와 실제 제작이 정해지면 ID별 상태·담당자·목표 빌드·검수 일자를 별도 제작 트래커에서 관리한다.

## 4. 제작·파일 규칙

### ID와 파일명

- 에셋 ID는 표의 고유 ID를 사용한다. 콘텐츠 배치 ID(`CH##_SEG##_PAT##`)와 모델/소스 에셋 ID를 분리한다.
- 권장 파일명: `TYPE_ID_subject_variant_state_locale_version` 형식. 예: `ANM_003_player_jump_land_ko_v001`.
- 공백과 특수문자는 피하고, 상태·방향이 필요한 스프라이트/클립은 접미사에 `left/right`, `idle/air/land`처럼 명시한다.
- 원본 작업 파일과 엔진 임포트 파일을 모두 보존하며, 파생 파일은 원본 ID를 유지한다.

### 소스와 전달 형식 (엔진 선정 전 제안)

| 종류 | 보존할 원본 | 엔진 전달 후보 | 결정 시점 |
|---|---|---|---|
| 3D 모델/리그/애니메이션 | 사용 DCC의 편집 원본 | FBX 또는 glTF 계열 | 엔진·렌더 파이프라인 결정 후 |
| 텍스처/아이콘/VFX 텍스처 | 편집 가능한 원본 | PNG/TGA 등 무손실 이미지 | 플랫폼 압축/아틀라스 규칙 확정 후 |
| UI 레이아웃/그래픽 | 편집 원본 및 폰트 라이선스 기록 | 엔진 UI 자산 및 벡터/래스터 이미지 | UI 기술 선택 후 |
| 효과음/음악 | 편집 세션과 무손실 마스터 | WAV 마스터 및 엔진별 압축본 | 오디오 엔진·플랫폼 목표 결정 후 |
| 문자열 | 키 기반 원본 테이블 | 프로젝트 현지화 시스템이 읽는 CSV/JSON 등 | 현지화 도구 선택 후 |

위 포맷은 작업 선택을 돕는 후보이며 엔진 확정 사양이 아니다. 실제 압축, 해상도, 폴리곤/텍스처 메모리, 프레임레이트, 플랫폼별 납품 값은 기술 기획에서 성능 목표와 함께 고정한다.

## 5. 공통 승인 기준

1. 모든 게임플레이 오브젝트는 `위험`, `수집`, `장식` 중 하나의 기능을 데이터에 명시한다. 장식은 충돌/수집 판정을 갖지 않는다.
2. 위험과 수집은 색 외에 실루엣·진입 동작·아이콘·효과음 중 하나 이상의 식별 단서를 추가로 가진다.
3. 점프 준비·공중·착지, 수집 성공, 근접 통과, 접촉·회복은 실제 플레이 속도에서 서로 혼동되지 않는다. 짧은 상태는 0.1초 표본으로 후보 구간을 검토하고, 60fps 재생/게임 재현으로 최종 확인한다.
4. 날씨/파티클/카메라 효과는 도로 경계와 위험 예고를 가리지 않는다. 화면 흔들림, 눈보라, 번쩍임은 설정으로 줄이거나 끌 수 있다.
5. 오디오가 꺼져도 핵심 위험·상태는 화면으로 파악 가능하고, 색약 팔레트에서도 위험과 보상을 구분할 수 있다.
6. 각 에셋은 원본 출처·제작자·라이선스·수정 이력·최종 승인자를 기록한다. 영상 분석 시트는 조사 근거로만 취급한다.

## 6. 미결정 사항

- 엔진, 렌더 파이프라인, 목표 해상도/FPS 및 플랫폼별 메모리 예산
- 첫 공개 빌드의 5종 상호작용 중 위험/수집 배분 및 정식 출시 위험물 세부 구성
- 모델 스타일(3D/2.5D), 캐릭터 수 4종의 플레이어 포함 여부, 의상 변형 제작 방식
- 음성 연기 필요 여부, 음악/효과음의 최종 곡 수, 다국어 범위와 납품 포맷
- 아트 제작 인력, 외주 범위, 일정과 예산

결정이 내려지면 이 문서의 수량·포맷·우선순위를 갱신하고, 제작 상태를 `계획 → 제작 → 검수 → 승인`으로 관리한다.

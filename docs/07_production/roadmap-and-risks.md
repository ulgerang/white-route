# 제작 로드맵과 위험

## 단계별 계획

| 단계 | 산출물 | 종료 조건 |
|---|---|---|
| 0. 종이 설계/회색 박스 | 한 구간, 좌우 조향, 잔여 거리/시간/속도 HUD | 초보가 10회 안에 위험과 수집물을 구분하고 기본 회피를 학습 |
| 1. 코어 검증 | 3개 위험, 2개 수집물, 점프 상태 피드백, 이벤트 텔레메트리 | 플레이테스트에서 위험/수집 및 공중/지면/접촉 상태를 구분. 짧은 이벤트는 0.1초 시트로 검토하고 60fps 재생으로 최종 확인 |
| 2. 수직 슬라이스 | 해안 구간 1개, HUD, 오디오, 결과 | 시작-주행-완주-재도전까지 완결되고 카메라/점프/충돌 피드백 확인 |
| 3. 콘텐츠 생산 | 5장/20구간 데이터와 아트 | 위험/난이도/접근성 기준 통과, 콘텐츠 규칙 검증 |
| 4. 안정화 | 저장, 설정, 현지화, 성능, 버그 수정 | 릴리스 체크리스트와 크래시/진행 차단 기준 충족 |

기간과 팀 규모는 엔진·인원·플랫폼이 미확정이라 산정하지 않는다. 0단계에서 제작 비용을 재평가한다.

## 주요 위험과 대응

| 위험 | 조기 신호 | 대응 |
|---|---|---|
| 추가 이동 기능으로 조작이 복잡해짐 | 플레이어가 점프/대시 대신 한 행동만 씀 | 행동별 위험 언어를 분리하고 필요 없는 버튼 제거 |
| 체온 게이지가 부가 관리가 됨 | HUD 확인이 회피보다 잦고 불만이 증가 | 체온을 버프/디버프로 축소하거나 제거 |
| 원근 시야에서 충돌이 불공정함 | 같은 패턴에서 예고 인지 실패가 잦음 | 위험 리드 타임, 카메라, 그림자 표식 조정 |
| 랜덤 패턴이 불가능한 조합을 만듦 | 특정 시드의 연속 충돌/시간 부족 | 검수된 패턴 블록과 안전공간 제약으로 제한 |
| 지식재산 혼동/의존 | 명칭·캐릭터·음악을 그대로 연상시킴 | 자체 명칭, 실루엣, 사운드, UI 제작 및 법률 검토 |
| 콘텐츠 소모 속도 | 완주 후 재플레이 이유가 없음 | 고정 시드 기록, 임무 변형, 경로 수제 조합 검증 |
| 상호작용 오독 | 플레이어가 같은 객체를 위험/수집으로 다르게 해석 | 실루엣·진입 모션·획득 피드백을 재설계하고 접촉 시트로 재검토 |
| 이벤트 원인/결과 오독 | 객체 통과와 점수 변화가 가까이 발생해 무엇을 획득했는지 모름 | 수집 대상 아이콘·점수·임무 갱신을 하나의 획득 이벤트에 묶고, 근접 통과/충돌에 별도 피드백 적용 |
| 점프/접촉 상태 불명확 | 0.1초 시트에서는 공중 전환이 보이지만 접촉 판정은 모호하거나 실시간 플레이어가 착지 상태를 놓침 | 준비·공중·착지 상태, 지면 그림자, 접촉 신호를 보강하고 60fps 연속 재생과 플레이테스트로 확인 |

## 우선순위

**P0:** 달리기, 조향, 잔여 거리·시간·속도 HUD, 위험 예고, 점프 피드백, 재시작.  
**P1:** 가속/감속 밸런스, 분기, 도착 판정, 결과/기록, 대시 프로토타입.  
**P2:** 체온, 구조 임무, 도감/꾸미기.  
**보류:** 실시간 온라인, 절차적 전체 코스, 대규모 생존 제작.
